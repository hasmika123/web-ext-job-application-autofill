## Answered decisions (user, 2026-10-15)

| **S-19** | **No-response default for a plan / add-on retirement = fall back to Free with a read-only lock.** When a subscriber never responds to the retirement notices, at the effective date (monthly/quarterly: end of the paid period; yearly: next renewal) the account moves to Free. Every service or add-on they were using that Free does not include is **locked read-only**: data stays visible and exportable; nothing new can be created or run in that service until they pick a plan or add-on that includes it again. **Nothing is deleted; unlocking is instant on upgrade.** Over-cap data (e.g. 12 resumes on a 3-resume Free) is kept in full, creating beyond the cap is blocked, nothing is archived or deleted by us. Enterprise equivalent: seats fall back to the base license and the seat's add-on data becomes read-only per seat. | 2026-10-15 | `11-plan-retirement.md` §7 (the per-service read-only table §7.1, the `LOCKED` tri-state in `EntitlementDecision.access` §7.2, the `service_lock` / `seat_service_lock` tables §10, notices §4.2 `retire.default.free`, UI lock states §12, tests §13); stories K10.5, K10.6, K10.7, K10.10, K10.11; setting `billing.retirement.default_outcome=FREE` (HIGH) is the shipped default and `MIGRATE_AT_RENEWAL` stays a per-retirement admin alternative only when no affected subscriber would pay more (S-21). |
