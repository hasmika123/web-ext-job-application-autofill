# Resume templates — decisions

Per the user's instruction (2026-10-17, "don't wait for my decision"), every question below is
**Decided (recommended), revisit if you disagree.** The build in `stories.md` assumes these. Reverting
one is a small follow-up story; none blocks the engineer.

| # | Question | Decided | Why |
|---|---|---|---|
| 1 | Widen `ATS_STRICT.theme.fontPairs` from `[inter, georgia-arial]` to every bundled font (five)? | **Yes.** | Fonts are embedded as real text in the PDF; the text layer is identical whichever face is used. Jobscan's own "web-safe" list includes Garamond and Georgia. The restriction only hid the user's font on every switch. Admin overrides can still narrow a template's menu. (DESIGN §3.1) |
| 2 | Ship eight `ats: true` templates before R3.6's parse-check gate exists (DESIGN §7.3 says an ATS template "must pass the parse-check gate")? | **Yes, with the structural compliance test now.** | R3.6 is not started and depends on R3.3; blocking ten templates on it would stall the whole track. `expectAtsCompliant` (no tables/images/svg/columns/icons, standard headings, no CSS-generated text) covers what the gate checks structurally. R3.6's gate test iterates `listTemplates().filter(ats)`, so it adopts all eight automatically when it lands. (DESIGN §12.2) |
| 3 | Enable all ten by default; default `modern`; Popular = `modern, engineer, classic, sidebar, compact`? | **Yes (user constraint).** | They appear without admin action; admin can disable or reorder through the existing settings. (DESIGN §9.1) |
| 4 | Bundle two new OFL fonts (IBM Plex Sans, EB Garamond; upright + italic, four woff2 files, ~200 KB)? | **Yes.** | `types.ts` already reserved Plex; Garamond is the banking/consulting serif and the only one with an OFL cut. Italic files are needed because three templates set italic lines by CSS. No runtime dependency; the PDF route already inlines `../fonts/*.woff2`. (DESIGN §4) |
| 5 | Build a federal (USAJOBS) template? | **No — dropped.** | Federal resumes need hours per week, supervisor name/phone, series/grade per role and run 2–5 pages; our schema has none of those fields and `maxPages` is 2. Faking it would mislead users. Revisit only with a schema change and a product decision. (DESIGN §1.3) |
| 6 | Should picking `consultant`/`scholar` on a new resume put Education first automatically? | **No in this track.** | Section order is the user's (Swap Section) and the seeder is server-side with no template knowledge. The description and `atsNote` state the convention ("Education first if you graduated in the last three years"). A later `meta.startOrder` mirrored in Java can add it. |
| 7 | Reuse the ids `classic` and `compact` that Java already accepts for the new Classic and Compact templates (no migration)? | **Yes.** | Additive and safe: the web never offered those ids, so no row holds them; a stray row would now render as the template its name promises. `KNOWN_TEMPLATE_IDS` becomes the ten and a parity test pins it to the shared fixture. (DESIGN §10) |
| 8 | Sidebar on the left visually, with DOM order header → main → aside? | **Yes.** | Reading order (and the PDF text layer) follows the DOM, so a parser gets the main column first; the tinted column on the left is the look users expect from "sidebar" templates. (DESIGN §6.10) |
| 9 | Thumbnails: how generated? | **A repo script, PNGs committed (user constraint).** | `web/scripts/render-template-thumbs.mjs` (`npm run thumbs:templates -w web`) spawns the guarded vitest generator with the env set, so it runs the same on Windows, macOS, Linux and the sidecar; a browser-free guard test checks every PNG is 240×340. (DESIGN §8) |
| 10 | Middle profile: a named `HYBRID` constant, or just tighten `DESIGN_FREE` inline in `statement`? | **Named `HYBRID`, mirrored in Java and the fixture.** | It is the natural profile for any future single-column coloured template and gives the gallery rating a stable anchor; the registry rule itself does not change (`ats: false` ⇒ ≤ `DESIGN_FREE`). (DESIGN §3.2) |
| 11 | Shared-renderer options (`layout`, `skills`, `sep`/`stacked`) vs. per-template item renderers? | **Shared options.** | Keeps the "renderer applies the rules, template places" contract; three small opt-in options cover all ten layouts; `modern`'s output is unchanged except the project-dates fix. (DESIGN §5) |
| 12 | Projects' `start`/`end` (in the schema, never rendered) — render them now? | **Yes, for every template.** | A silent data loss; one shared change, snapshots updated once. (DESIGN §5.4) |
| 13 | Where does the per-template category live? | **`meta.category` + `meta.atsNote` in TypeScript only.** | The API never reads them; mirroring would add parity surface for nothing. (DESIGN §3.5) |
| 14 | Should `consultant` lock one page (`maxPages: 1`, Page Length fixed)? | **Yes.** | Every consulting/banking source says strictly one page; the capability system already supports the tightening and the UI already shows "(fixed by this template)". `engineer` stays at 2 (senior engineers legitimately run two). (DESIGN §3.4) |
| 15 | Regenerate `modern.png` too? | **Yes.** | All ten thumbnails show the same fictional person from the same fixture, so the gallery compares layouts, not content. |
