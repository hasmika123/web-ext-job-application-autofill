## Questions and gaps in the server contract (for Track A, S6)

1. **Where the new handoff fields live.** I assumed they sit inside the `tokens` object next to `access`/`refresh`/`username` (`{type: "KIWIPLY_CONNECT", tokens: {access, refresh, kind, orgId, orgName, email, userId}}`). The handoff text says "existing token fields plus ...", which is ambiguous. Please confirm or tell me to read them from the message top level.
2. **Required fields.** The extension refuses an ENTERPRISE handoff without a positive integer `orgId` **and** `userId` (`invalid-account`). The web `/connect` page should show that failure, and the personal handoff should send `kind: "PERSONAL"`, `userId` and `email` too (without `userId` the extension can only compare usernames, a one-time bridge for sessions from before this release).
3. **Allow-list paths in doc 19 section 6.2 do not match the real routes.** The extension calls `/api/profile` (GET/PUT), `/api/profile/version`, `/api/profile/resumes[/{id}]`, `/api/profile/applications[/{id}]`, `/api/profile/field-caches/sync`, `/api/profile/suggestions`, `/api/ai/{usage,draft,job-fit,parse-resume,resume-match}`, `/api/telemetry/fills[/{id}]`, `/api/bug-reports` (plural), `/api/refresh`, `/api/logout`, plus `/api/orgs/{orgId}/con/opportunities...` and `/api/orgs/{orgId}/mkt/opportunities/...`. The doc lists `/api/resumes/**`, `/api/application*`, `/api/field-cache*`, `/api/fill-telemetry`, `/api/bug-report`, which would 403 the real client. Please build the world-check allow-list from the list above.
4. **Refresh.** An enterprise extension token must refresh through `POST /api/refresh` on `api.kiwiply.com` (a platform host) and keep `ext=1` and `tid`. The client only sends the refresh token. Not verifiable here.
5. **`account` shape.** I rely on `account.kind` being exactly `"PERSONAL"` or `"ENTERPRISE"`, `orgId` a positive integer for enterprise, and `consultant`/`marketer` real booleans (anything else is treated as false). For an enterprise token, `account.name` should be the organization name.
6. **`workspaces[]` fallback risk.** An older server sends `workspaces[]` for a *personal* user who belongs to an org. If such a user's session has no `kind` (connected before this release) the fallback reads it as enterprise. After S6 every session carries a `kind`, so this only matters during the one-release overlap; sending `account` from S6 removes it.
7. **Marketer-only enterprise accounts** call `GET /api/profile/version` on every drawer open to learn their roles (no profile read). That route must stay reachable for them.
8. **Switch account** for an enterprise to personal opens `https://kiwiply.com/connect`; personal to enterprise is only an instruction ("Connect extension" in the workspace) because tenant hosts vary. If S6 adds a stable platform URL that lists or redirects to the person's enterprise workspaces, the panel can link it.
