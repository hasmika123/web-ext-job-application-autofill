## 4. Security findings to fix first (feed A0/A9)

1. Google sign-in issues admin tokens with no MFA (`GoogleAuthController.java:81-85`).
2. Refresh copies `authorities` from the old token; revoke-admin doesn't revoke families → ROLE_ADMIN survives up to 90 days (`AuthenticateController.java:197-204`, `AdminUserActionService.java:88-110`).
3. API rate limiting off (`RATE_LIMIT_ENABLED=false`) and spoofable key; no rules for MFA/google/refresh/intake.
4. `UserResource` PUT/DELETE bypass audit + self-guards; DELETE uses plain `userService.deleteUser` (FK failures likely).
5. `/management/info` public with full git + env info.
6. Subscriber CSV export unaudited, no formula-injection guard.
7. `AdminBootstrap` resets the matched account's password hash on every boot (by design, but document it); default `ADMIN_LOGIN=admin` could take over a surviving prod `admin` row.
8. `ai_quota_override` keyed by login survives account deletion.

## 5. Mobile reality

Shell is responsive (drawer, 2×2 tiles, scrolling tabs, `overflow-x-auto` tables) but no admin page is *designed* for a phone: no triage views, no bottom sheets, no 44 px audit, no dark-mode check, search hidden on phones. See PLAN-admin.md "Mobile admin stance".
