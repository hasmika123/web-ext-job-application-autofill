# ADR-024 — Revision 2 (2026-10-13): Phase 1 scope decision + adopted review amendments

> Amends `ADR-024-job-opportunity-model.md` (read that first). Status: proposed, under review. Companion: `../59-job-phase1-extension-flow.md`.

**Owner decision:** job search/discovery, public pools, connectors and matching engines are **Phase 2**. Phase 1 (needed for Release 1) is the extension-driven flow of doc 59: the marketer captures *trimmed* job details with the extension and assigns them; the consultant opens the source link and applies with their own extension (or applies anywhere on their own); we track the application. It matches the already-written stories X9.2/X9.9/X9.12 and `32-applications.md` §2.

**Independent Fable reviews** (two adversarial reviews of docs 50–58; ~55 claims re-verified against code) found the current-state analysis accurate (one error: the "one primary resume" unique key already exists, `ent_talent.xml:477-482`) and produced the amendments below. Each is adopted unless marked.

## Deferred to Phase 2 (kept as the target design, not built now)
D-2 (`org_job_source_occurrence` + MISSING/EXPIRED machine: no producer exists), D-3 (adopt-from-public; field overrides replaced by `sync_mode FOLLOW|DETACHED` when built), D-4 layer-3 merge (replace by `duplicate_of_id` soft-hide when built), D-6 stale scheduler (replace by bounded synchronous recompute; one `components` JSON column instead of six), D-8 saved jobs, job search/discovery, consultant Job Matches. Public-source licensing becomes a Phase 2 gate; Phase 1 stores only trimmed facts plus the source URL.

## Decisions changed
- **D-1** keeps `client_requirement` as the in-tenant job; Phase 1 adds URL identity (`job_url`, `url_key`, `external_job_id`, `ats_platform`, `capture_source`, `captured_by_member_id`) with UNIQUE `(org_id, url_key)` and `(org_id, ats_platform, external_job_id)`. Employer = `client_account` find-or-create by `name_key`. No full description stored.
- **Lifecycle (D-7)** reduced to ASSIGNED, VIEWED, INTERESTED | DECLINED | NEEDS_INFO, APPLIED, CLOSED. `DECLINED` from any non-CLOSED state; the marketer answers a question with an `INFO_PROVIDED` event, never by setting the consultant's state; one withdrawal concept (opportunity CLOSED/WITHDRAWN freezes the match, match-level WITHDRAWN dropped); reopen when the job reopens; `mkt_opportunity` rows only for ASSIGNED matches.
- **D-9** one direction only: `talent_application.submission_id`; `mkt_submission.application_id` dropped.
- **D-10 (submission/authorization, ADR-010)**: **no admin override for consultants who have a seat.** `authorization_basis` is `CONSULTANT` or `ORG_ATTESTED`; `ORG_ATTESTED` is legal only when `consultant_profile.member_id IS NULL`, needs evidence (`channel_label` + `external_reference`) and a reason, is HIGH-audited, and is emailed to the consultant if an address exists. New `authorization_scope` (`APPLY_SELF`, `SUBMIT_RECORD`, `BOTH`; binding in `31` §4/§9); job-board jobs forbid `SUBMIT_RECORD`; a marketer-recorded `SUBMITTED` requires scope including SUBMIT_RECORD; `channel_label` distinguishes `CONSULTANT_APPLIED` from `MARKETER_PRESENTED`. The live-uniqueness key excludes REJECTED/REVOKED/archived rows. Revoking one submission is separate from revoking consent (`DataShareService.revoke` cascades to submissions, never the reverse). This block is **Phase 1b** because it needs the consultant API; until then the Submissions page's marketer-recorded approval is a documented deviation from ADR-010 (finding F1).
- **D-12 concurrency**: `version BIGINT NOT NULL DEFAULT 0` (a nullable `@Version` makes `isNew()` true and breaks saves); `DataIntegrityViolationException` is translated in a `@ControllerAdvice` scoped to the `mkt` and `con` web packages (re-read in a new transaction, 200-existing or 409), because it surfaces at flush/commit after the service method returns; `Idempotency-Key` is required on **creates** (from-extension, assign, apply link); same-target-state transitions return 200.
- **D-13** `ConScope` requires the caller's seat to have exactly one `consultant_profile` (the unique `(org_id, member_id)` exists, `ent_talent.xml:105-106`); shared job services take a mandatory scope object, never a bare `orgId`; a DTO-reflection test (no other-consultant or marketer fields in `Con*` DTOs) is P0.
- **D-15** one canonical job-details URL `/w/consultant/opportunities/[id]`, rendered as an intercepting route (drawer) on wide screens and a full screen on compact; the compact breakpoint covers landscape tablets via `(max-width:1023px), (pointer: coarse) and (max-width:1366px)` pending owner sign-off; the `context` query parameter is dropped (the server returns every block the caller is entitled to); separate `ConJobDetails` and `MktJobDetails` compositions over shared section components; the source URL and the real employer name are always shown at authorization/apply time.
- **Q-2 closed:** assignment history uses `org_assignment` (`D/17`, already read by offboarding hooks), not a new table. **Q-3 closed:** the personal `application` stays the source of truth; org rows are consent-filtered projections linked by `pipeline_application_link`. The `resumes.approve` key is dropped: reuse `resumes.manage` (OWN).
- **Licensing:** assigning a job or creating a draft consumes `marketing.assisted_applications` on the consultant's licence (`37` row 7): the call site is added now with quantity 0 until `EntitlementCheckStep` exists; `consultant_jobs.ai_scoring_enabled` is an operational kill switch removed later; `GET /con/features` is the single source of the `license` block.

## Corrections to the factual record (docs 50, 51, 56)
- The `repository.ent` contract test exists but all 17 `repository/ent/talent/*` repositories extended `JpaRepository` (P0 fix in progress, branch `fix-talent-repo-contract`); the R1–R10 "CI policy tests" named in doc 41 do not exist; the database is **MySQL 9.2** (Testcontainers and production), so generated columns, CHECK and FULLTEXT are available; `requirement_match.score` is `smallint`; FULLTEXT cannot satisfy R1 "index starts with org_id" (explicit exception needed); consultants without a seat are treated as FULL consent by current code (`MktApplicationsService.java:229-231`) and the design must state that policy (seat-less = ORG_ATTESTED, informational in Phase 1).
- `OrgResume.approvalStatus` defaults to `"APPROVED"` on the entity (`OrgResume.java:53`): any creator that forgets to set it bypasses the approval gate, so default to `PENDING` (P0 code fix).
- `NoSubmitSurfaceTest`, named in ADR-010, does not exist: add it (no org route sets `application.status`; no endpoint under `/api/orgs/**` transmits a submission).
