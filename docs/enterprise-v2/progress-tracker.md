The "tenant routes" of 04 s3 are interpreted as that org surface, not every route: a personal token on a tenant host still reaches `/api/account` and any user route; only org routes demand a bound session. The filter only inspects JWT authentications, so existing `user(...)` MockMvc tests are untouched. (2) `TenantTokenBinding` lives in `config` (not `security`): ArchUnit forbids Security -> Service and it reads the tenant context. (3) `AuthenticateController`/`GoogleAuthController` take `ObjectProvider<TenantSessionService>` because the sliced `AuthenticationIntegrationTest` hand-lists beans; no change to that slice. The membership check runs right after the password check and BEFORE the admin MFA mail, so a non-member never triggers a code. A bad password stays the ordinary 401 (no membership oracle without the password). (5) Refresh on a bound token re-checks the seat (suspended or removed = 401 at the next refresh, before the token is rotated) and requires the tenant host to match; a platform or no-host refresh of a bound token is allowed and keeps the binding. - 2026-10-12 — Phase 1 (X1.1-X1.5) code-review fixes on `ev2-build-p1` (Sonnet), commits `ent-fix: ...` x5. Fixed: anonymous `/api/public/tenant` no longer returns the org status; web forwards the visitor IP and the API reads the LAST X-Forwarded-For hop; 429/5xx are a "try again" page not "doesn't exist"; the API only believes `X-Kiwiply-Host` with a shared secret; resolver cache evicted on org close/suspend and on `flag.enterprise*` / `enterprise.hosts.*` admin writes; subdomain-only reserved labels; migration rollbacks and one changeset per column; negative cache + per-IP miss bound; no `localhost` defaults in production; flag-off outages keep legacy behaviour; unread registry keys hidden. Tests: API unit 1517 + integration 1052 green, web 2042 green, `npm run build -w web` green.
  - **Decisions I made:** (1) **Shared secret** `dossier.tenant-host.secret` (env `DOSSIER_TENANT_HOST_SECRET`, header `X-Kiwiply-Host-Secret`, SHA-256 digests compared with `MessageDigest.isEqual`; a repeated header is a miss). Blank + `require-secret=false` (default; dev and tests) believes the host and logs one WARN; the prod profile sets `require-secret=true`, so a forgotten secret means NO host is believed (legacy behaviour, tenant hosts dark) and one ERROR, never trust-by-default. Compose passes it to both `api` and `web`; DEPLOY.md and both `.env.example` files document it. Deploy action for the user: set `DOSSIER_TENANT_HOST_SECRET` in the box `.env` before turning `flag.enterprise` on. (2) A request without a valid secret becomes `UNKNOWN/NO_HOST` (a legacy caller), not a 404, so a forged host can neither select a tenant nor probe with a different answer; `TenantHostSecretIT` proves public tenant, session binding and org-route authorization all ignore it. (3) **429/5xx/timeouts are a new web state `UNAVAILABLE`** (try-again page, HTTP 200, noindex), not UNKNOWN; it is also what a non-platform host gets when the config endpoint is unreachable AFTER the flag was last seen on. When the flag was never seen on in this process, an unreachable API means legacy PLATFORM behaviour (finding 9). A fresh process with the API down and the flag actually on therefore serves the platform for a tenant host until the API answers once: accepted trade-off, the API still refuses tenant data without a host. (4) Visitor IP: only the last forwarded hop (`clientIpFromHeaders`) is sent, and only on tenant-host calls (serverApiFetch with a host, tenant resolution, auth BFF), so the API's existing per-IP auth limits on platform traffic are unchanged. (5) `TRUST_PROXY_HOST` (web, default true) gates `x-forwarded-host`; production sits behind the shared edge Caddy which overwrites it. (6) **Eviction by event**: `TenantConfigChangedEvent` (`@TransactionalEventListener` AFTER_COMMIT, fallback when no transaction) published by `OrgService.close`, the owner-less suspend in `OrgMembershipPrivacyService`, and `AdminSettingsWriter` for `flag.enterprise*` / `enterprise.hosts.*` keys. Those are the only places an organization status is written today (there is no admin suspend/reinstate or Stripe PAST_DUE writer yet): whichever story adds one must publish the event. `AdminSettingsWriter` and `OrgMembershipPrivacyService` gained an `ApplicationEventPublisher` constructor argument. Another API instance still converges within `enterprise.tenant.cache_seconds`. (7) **Negative cache**: UNKNOWN_HOST answers live in a separate map (2000 entries, at most 5 s), so a hostname scan cannot evict real tenants; ORG_INACTIVE / FLAG_OFF stay in the main cache. Per-visitor miss bound `dossier.tenant-host.misses-per-minute` (default 120, a fixed window per address, 10000 addresses tracked); over it a miss answers UNKNOWN without a database lookup and is not cached. Tests raise it to 1000000 because every MockMvc request is 127.0.0.1. The counter is a small private class, not `FixedWindowRateLimiter`, because ArchUnit forbids service to web. (8) **localhost**: removed from the `enterprise.hosts.platform` and `tenant_base_domains` defaults; loopback is still always PLATFORM in the resolver; `acme.localhost` works only when `dossier.tenant-host.allow-localhost-tenants=true` (dev profile and the test config; false in prod and ignored even if an admin lists `localhost`). The web keeps its platform list as a documented fast path and the API setting is the single source of truth (they differ by design: web derives from `SITE_URL`). (9) **Hidden settings**: 13 keys nothing reads (five sub-flags, three domain knobs, invite email match, consent cooldown, billing mode, quote TTL, usage retention) moved to `EnterpriseSettingKeys.deferred()`: constants stay, they are not registered, so admin never offers them. The story that starts reading one moves its declaration to the live list. `EnterpriseFeatureFlag` reads an unregistered flag as off (it already fails closed). (11) Migration: `-4` and `-6` keep their ids but now add one column each, with `validCheckSum ANY` so a developer database that already ran the old text accepts them; `-4b/-4c/-4d/-6b/-6c` are new, each with a column precondition; `-1` and `-5` have `<rollback>`. `EntTenancySchemaIT` is proven to run on MySQL 9.2 (Testcontainers) by an in-test assertion on `VERSION()` and on the generated columns.
