# 60 — Phase 1 implementation contract (AUTHORITATIVE for WP1–WP5; supersedes doc 59 §5/§7/§8/§9 where they differ)

> Result of the independent Fable review of doc 59 (verdict: **go with changes**, 2026-10-13). Builders code against THIS document; doc 59 gives the story. Evidence labels: V = verified in code by the review. Naming: marketer = `mkt`, consultant = `con`. Repositories under `repository/ent/**` extend ONLY `org.springframework.data.repository.Repository<T,Long>` and take `orgId` first (`EntRepositoryContractTest` — passing since `65b56dd8`). Hard rules: no auto-submit; a marketer or Kiwiply never sets a consultant's application status; a marketer extension session never loads a consultant's bio/answers; no server-side fetch of `jobUrl` in Phase 1 (no SSRF); all free text through `SensitiveContent.check`.

## 0. Decisions adopted from the review
1. **No `X-Kiwiply-Workspace` filter and no `GET /api/profile/assigned-jobs`.** A user-only extension token already reaches `/api/orgs/{orgId}/**` on a platform host (V: `TenantResolverFilter.java:60-62`, `TenantTokenBindingFilter.java:49-68`, `OrgPermissionInterceptor.java:85-106`, `AuthorizationService.java:83-93`). The consultant extension calls `GET /api/orgs/{orgId}/con/opportunities`. The only new profile-side change: `workspaces[]` on `GET /api/profile/version`.
2. **Automatic APPLIED detection exists only where the extension fills** (Workday, Greenhouse, Lever, Ashby, Workable, iCIMS, Taleo, SmartRecruiters, BambooHR, Jobvite, Indeed SmartApply) (V: `service-worker.js:545-546,653-664`, `wxt.config.ts:117-139`). On LinkedIn Easy Apply and Dice native apply nothing is detected, so **"I applied" is a first-class path** (drawer and web), and UI copy says so.
3. **Consent (resolves the SUMMARY/FULL contradiction; V `ShareField.java`)**: (a) flipping the *opportunity* to APPLIED is an org-side fact about an org-created assignment: allowed at scope ≥ SUMMARY, never at NONE — except through the consultant's own explicit "I applied"/link click, which is itself a share of that single fact; (b) a `talent_application` projection row with stage detail requires FULL; (c) NONE ⇒ no link, no projection, honest empty state. `MktApplicationsService.consentOf` must return SUMMARY (not FULL) for seat-less consultants (`:229-234`).
4. **Stage ownership.** If `talent_application.personal_application_id IS NOT NULL` the row is SYSTEM-owned: marketer `recordStage` returns 409 `STAGE_OWNED_BY_CONSULTANT`. Marketer `recordStage` stays only for rows with `capture_source ∈ {MANUAL, CLIENT}` and no link. `stage_source` records the last writer.
5. **Hook point.** `ApplicationEventService.record()` is the single writer (V `:76-125`; `recordStatus` returns a boolean and publishes nothing): publish `ApplicationEventRecorded` there (covers created and status changes).
6. **`from-extension` never accepts `state`/`appliedAt`, waives the approved-resume gate for `capture_source=EXTENSION`** (APPLY_SELF; otherwise the flow dead-ends on `RESUME_NOT_APPROVED`, V `MktOpportunitiesService.java:383-397`), and never fetches the URL.
7. **Identity:** `url_key` is built in Java (not a generated column); UNIQUE is on `url_key_hash`. Company+title matching is only a **suggestion** the consultant confirms (never auto-link).
8. **Seat-less consultants (`member_id IS NULL`):** informational only in Phase 1; a marketer-recorded "consultant says applied" is an event, never `applied_at`/state APPLIED.
9. **Interest vs state:** `mkt_opportunity.interest` becomes legacy/derived (INTERESTED→`state=INTERESTED`, NOT_INTERESTED→`DECLINED`); new code writes `state` only.
10. **Deferred:** `data_share.share_direct_applications` (direct-path opt-in), `WorkspaceHeaderFilter`, storage partition per workspace, SSE (poll), save-to-board, resume-stale, consent-gate refactor across matches/resumes, consultant authorization of vendor submissions (Phase 1b).

## 2. Shared Java rules
- `UrlKeys` (new, `service/ent/jobs/`): `normalize(url)` = `ApplicationKeys.url()` rules + lowercase scheme/host, drop fragment, drop `currentJobId` only when it was used as `externalJobId`, cap 1000; `hash = sha256hex(normalized)`. Golden test file shared with `ApplicationSyncService` expectations. `https:` only, host not IP/loopback/localhost, ≤1000 chars, else 400 `VALIDATION`.
- `OpportunityAssignmentService` (`service/ent/mkt/` or `service/ent/jobs/`): the **only** code that creates/reopens `requirement_match` + `mkt_opportunity` for a (job, consultant); used by `MktOpportunitiesService.assign`, `MktMatchesService.assign`, `MktJobsService.assign` and `from-extension`. Rules: job must be OPEN/IN_REVIEW (409 `JOB_NOT_OPEN`); consultant `status` and `marketing_status` ACTIVE (else result reason `CONSULTANT_INACTIVE`); scope via `MktScope.require`; resume gate only when `capture_source <> 'EXTENSION'` (409 `RESUME_NOT_APPROVED` kept for others); pair exists ⇒ if DISMISSED/DECLINED/CLOSED reopen to ASSIGNED with event `REASSIGNED`, if already ASSIGNED ⇒ `existing=true` (no error); audit + event; consultant notification record.
- Find-or-create with retry: `client_account` by `(org_id, lower(name))` (add repository query on the generated `name_key`), `client_requirement` by `url_key_hash` then `(ats_platform, external_job_id)`, `requirement_match` by pair — each insert in `REQUIRES_NEW` with re-read on `DataIntegrityViolationException`. PLUS a `@ControllerAdvice` for `web.rest.ent.mkt|con` mapping an unhandled violation to 409 `CONFLICT` (re-read where possible). Services never rely on the advice alone.
- `ConScope` (`service/ent/con/`): roles-from-data on + `flag.enterprise.consultant_jobs` + permission (`opportunities.respond`, OWN) + the caller's seat has exactly ONE `consultant_profile(org_id, member_id)` and `status` ACTIVE; resolves `consultantId` itself — **never taken from the request**; any miss = generic 404.
- Lifecycle service (`ConOpportunityService`): the matrix below; same-target = 200 no-op; `@Version` conflict = 409 `VERSION_CONFLICT`; each transition = one transaction + `mkt_opportunity_event` + `org_audit_event`.

## 3. Lifecycle matrix (`mkt_opportunity.state`) — actors C = consultant (OWN), M = marketer, S = system
| From | To | Actor | Trigger |
|---|---|---|---|
| ASSIGNED | VIEWED | C | `POST …/viewed` (explicit; never a GET side effect) |
| ASSIGNED, VIEWED, NEEDS_INFO | INTERESTED | C | `POST …/interest` |
| ASSIGNED, VIEWED, INTERESTED | NEEDS_INFO | C | `POST …/request-info` (marketer gets a task + notification) |
| NEEDS_INFO | NEEDS_INFO | M | `POST mkt/…/answer-info` sets `info_answer`, event `INFO_PROVIDED` (state unchanged; consultant then answers with interest/decline) |
| ASSIGNED, VIEWED, INTERESTED, NEEDS_INFO | DECLINED | C | `POST …/decline` (sovereign: allowed from any non-terminal state) |
| DECLINED | INTERESTED | C | `POST …/interest` while the job is open |
| ASSIGNED, VIEWED, INTERESTED, NEEDS_INFO | APPLIED | C, S | consultant `POST …/applied` or `…/link`; S = `PipelineApplicationLinker` (consultant's own submit) — **never M** |
| any non-CLOSED | CLOSED | M, S | job closed/filled; marketer withdraws (`closed_reason=WITHDRAWN`, freezes the match); linked application REJECTED/WITHDRAWN (`APPLICATION_TERMINAL`); consultant inactive (`CONSULTANT_INACTIVE`) |
| DECLINED, CLOSED | ASSIGNED | M | re-assign (event `REASSIGNED`; same `requirement_match` row) |
`OFFER` on a linked application keeps APPLIED (nudge only). No path sets APPLIED from the marketer side.

## 4. Endpoints (JSON; all `/api/orgs/{orgId}/**` behind `@OrgPermissionRequired`; anything out of scope = generic 404)
**Marketer — `POST /api/orgs/{orgId}/mkt/opportunities/from-extension`** (user token from the extension or web). Gate: `MktScope.resolve(me,"opportunities.manage")` + `require(view, id)` per consultant. Header `Idempotency-Key` (UUID, required, 400 `IDEMPOTENCY_KEY_MISSING`). Body ≤ 8 KB: `{jobUrl:string(https,≤1000,req), title:string(1..300,req), company:string(1..200,req), location?:≤300, workMode?:REMOTE|HYBRID|ONSITE, employmentType?:≤20, payLabel?:≤80, payMin?:int, payMax?:int, payPeriod?:HOUR|YEAR|MONTH, externalJobId?:≤200, atsPlatform?:≤40, postedOn?:date, skills?:string[≤8]≤60 each, keyInfo:string(1..1000,req), priority?:LOW|MEDIUM|HIGH, dueOn?:date, consultantIds:long[1..20]}`. Unknown fields rejected (400). Response 200: `{jobId, existingJob:bool, results:[{consultantId, opportunityId, existing:bool, reason?:CONSULTANT_INACTIVE|NOT_IN_SCOPE}]}` (a consultant out of scope is reported, not a 404 for the whole call). Errors: 400 `VALIDATION`, 422 `SENSITIVE_CONTENT`, 409 `JOB_NOT_OPEN` (existing job closed). Stores: `client_requirement(capture_source=EXTENSION, description_text=keyInfo-derived summary ≤4000, status OPEN, source EXTENSION, captured_by)`, `requirement_skill` rows, rates (`pay*` → rate fields in minor units), per-consultant `marketer_note=keyInfo`.
**Marketer — `POST …/mkt/opportunities/{id}/answer-info {answer:1..1000}`**, `opportunities.manage`, scope-checked.
**Consultant — `GET …/con/opportunities?state=&page=&size=`** → `{items:[ConOpportunityDTO], total}`; `GET …/con/opportunities/{id}`; `POST …/{id}/viewed {}`; `…/interest {}`; `…/decline {reason: NOT_INTERESTED|LOCATION|RATE|ALREADY_APPLIED|OTHER, note?:≤200}`; `…/request-info {question:1..500}`; `…/applied {applicationId?:long}` (creates the link `source=CONSULTANT`; the application must belong to the caller: verify with `ApplicationRepository.findOneByIdAndUserId`, else 404); `…/link {applicationId}`; `…/unlink {}`. Optional `If-Match: <version>`. `ConOpportunityDTO = {id, state, job:{id,title,company,location,workMode,employmentType,payLabel,jobUrl,atsPlatform,externalJobId,postedOn,skills[]}, marketerNote, assignedBy:{memberId,name}, assignedAt, priority, dueOn, infoRequest, infoAnswer, appliedAt, linkedApplicationId, allowedActions[VIEWED|INTEREST|DECLINE|REQUEST_INFO|APPLIED|LINK|UNLINK], version}`. **Forbidden fields in any `Con*` DTO** (reflection test): rates beyond `payLabel`, client contacts, other consultants, marketer-internal notes, `ownerMemberId`.
**Profile — `GET /api/profile/version`** adds `workspaces:[{orgId,name,consultant:bool,marketer:bool}]` (ACTIVE memberships, roles-from-data + MARKETING on; `consultant` = has a `consultant_profile`; `marketer` = holds `opportunities.manage`). Additive; the extension ignores unknown fields.

## 5. Events and the linker
- `ApplicationEventService.record()` publishes `ApplicationEventRecorded(userId, applicationId, kind, fromStatus, toStatus, source)` after save (Spring `ApplicationEventPublisher`).
- `PipelineApplicationLinker`: `@TransactionalEventListener(AFTER_COMMIT)` + `@Transactional(REQUIRES_NEW)`, catch-all + log (never fail the user's write). On `toStatus=APPLIED` (or created APPLIED/SAVED): for each ACTIVE consultant membership of `userId`: consent ≥ SUMMARY (`DataShareService`), find open opportunities (state ∉ DECLINED, CLOSED, APPLIED) whose job matches by `(ats_platform, external_job_id)` then `url_key_hash`; link (`source=LINKER`), `state=APPLIED`, `applied_at`, event + marketer notification; if scope FULL upsert `talent_application(entry_path=LINKED, stage_source=SYSTEM, personal_application_id)`; on REJECTED/WITHDRAWN → CLOSED (`APPLICATION_TERMINAL`). Company+title ⇒ only an event `LINK_SUGGESTED` (consultant confirms in UI). Idempotent on the live link key.
- `NoSubmitSurfaceTest` (new, `src/test`): (1) no controller under `web/rest/ent/**` or `web/rest/org/**` can write `Application.status`; (2) no route under `/api/orgs/**` is named or documented as transmitting a submission; (3) from-extension rejects `state`/`appliedAt`. Must be green before WP3 merges.
