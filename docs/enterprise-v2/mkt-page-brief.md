# Marketing workspace (`mkt`) page brief — read this before building any `/w/marketing/**` page

Branch family: `ent-talent-marketer` (base) → one topic branch per page (`mkt-<page>`). You never push to `ent-talent`, `ent-all`, `version2`, `main`, `develop`, or `ent-talent-marketer`; you work and commit on your own `mkt-<page>` branch and report back. The owner merges.

## The job
Build ONE page of the Marketing Specialist workspace **exactly like its board image**, wired to a **real backend** (own API, own service, own tables when needed), end to end:
board image → web page → BFF route → Spring REST resource → service → repositories/tables → tests. Boards are in `design/enterprise-marketer/<page>.webp` (open them with the Read tool; read every pixel: titles, subtitles, KPI labels, column headers, row text, chips, buttons, filters, empty cards, section order, widths). **Match the board exactly**: same cards in the same grid, same labels/copy, same icons, same colours (tenant tokens only), same bee/photos. Do not restyle, rename or "improve". If the board shows something the data cannot honestly provide, still draw it from the real API (empty state when no rows, never fake numbers).

## Naming and isolation (user rule: every role has its OWN APIs; marketer = `mkt`)
- API base: `GET|POST|PATCH /api/orgs/{orgId}/mkt/<page>[/...]`. Java: resource `com.dossier.api.web.rest.ent.mkt.Mkt<Page>Resource`, service `com.dossier.api.service.ent.mkt.<page>.Mkt<Page>Service` (+ DTO records in the same package), repositories you add go in `com.dossier.api.repository.ent.mkt` as `Mkt<Thing>Repository`; new entities in `com.dossier.api.domain.ent.mkt`. **Do not edit the existing admin endpoints/services or the talent repositories**; add your own org-scoped query methods in your own `Mkt*Repository` (JPQL `@Query` over the existing entities) instead of changing shared interfaces.
- New tables are named `mkt_<thing>` and go ONLY in your pre-registered, currently empty changelog `api/src/main/resources/config/liquibase/changelog/<ts>_mkt_<page>.xml` (already included in `master.xml`; do not touch master.xml). Rules: `docs/enterprise-v2/41-database-design.md` R1–R10 (org_id NOT NULL + FK organization, every index starts with org_id, composite tenant FK `(org_id, parent_id)` to the parent's unique `(org_id, id)` key, varchar enum names, DATETIME(6) UTC, precondition-guarded changeSet per table, additive only, no sensitive PII: no SSN/bank/tax/passport/DOB/phone). Add entity + `Mkt*Repository` with every method taking `orgId` first. Seed demo rows for your new tables from a **new** class `com.dossier.api.service.ent.mkt.<page>.Mkt<Page>DemoSeeder` (idempotent: skip when the org already has rows; runs only when `ENT_DEMO_SEED=true`; hook it by implementing the same interface/`@Component` + `@Order` pattern `TalentDemoSeeder` uses — read how `EnterpriseDemoBootstrap` calls seeders; if hooking needs an edit of a shared class, make it a one-line additive edit and say so in your report).
- Access: every endpoint goes through `com.dossier.api.service.ent.mkt.MktScope.resolve(me, "<permission key>")` (already written; read it). It returns the generic 404 for non-members/flag-off/missing permission and the set of consultant ids the caller may see (ASSIGNED = consultants with a `marketer_assignment` naming the caller as marketer or backup; ORG scope sees all). Filter EVERYTHING by `view.sees(consultantId)`; a consultant id outside it is a 404. Permission keys per page: home `consultants.view`; talent `consultants.view`; resumes `resumes.view_for`; jobs/matches/streams `matches.run`; opportunities `opportunities.manage`; submissions `submissions.record`; applications `member.view_summary`; interviews `interviews.coordinate`; followups `followups.manage`. Write actions need the write key from `docs/enterprise-v2/talent-foundation.md` §4.
- **E1 (hard rule):** a marketer prepares, requests and records; the **consultant submits**. Never build an action that submits an application for a consultant, signs in as them, or auto-submits. "Submit to Job", "Assign", "Request Resume" etc. create a *record/request* (e.g. a draft submission, an opportunity assignment, a follow-up/request row), never a submission to a client. Consent badges where the board shows them. No sensitive PII anywhere.
- Web, new files only: component folder `web/src/components/ent/marketer-ws/<page>/` (the stub `<Page>Page.tsx` is pre-registered in `registry.tsx`: **replace the stub's body, keep the default export + `MktPageProps`**), lib `web/src/lib/ent/marketer-ws/<page>.ts` (types, lenient `parse`, `fetch`), BFF `web/src/app/api/orgs/[orgId]/mkt/<page>/**/route.ts` (copy `mkt/home/route.ts`; `forward()` from `@/lib/admin-proxy`; the BFF validates only the id shape), dev mock `web/scripts/mock-mkt-<page>.mjs` (stub pre-wired; the board's rows, see `mock-mkt-home.mjs`), tests beside the files. Shared pieces: use `@/components/ent/marketer-ws/parts` (`KpiTile`, `Head`, `HelpBannerCard`, `Empty`, `More`, `CardSkeleton`, `CARD`, `TINTS`) and `@kiwiply/ui` (icons, `Sparkline`, `DeltaChip`, `FunnelChart`, `SourceLogo`, `MemberAvatar`, `Select`, `Badge`, `Button`, `DataTable`/`FilterBar` in `packages/ui/src/enterprise`). **Do not edit** `registry.tsx`, `parts.tsx`, the shell (`components/ent/shell/**`), `workspaces.json`, `master.xml`, `mock-api.mjs`, `mock-mkt.mjs`, `OrgIsolationIT`. If you need a new shared visual (donut, stacked bar, toggle...), add it as a NEW file in `packages/ui/src/enterprise/<name>.tsx` + one export line at the end of `packages/ui/src/enterprise/index.ts` (additive; no inline `<svg>` outside packages/ui). If `parts.tsx` lacks something you need, build it locally in your folder.
- Theme: tenant tokens only (`bg-accent`, `text-accent-deep`, `bg-accent-soft`, `border-line`, `bg-paper`, `bg-paper-2`, `text-ink`, `text-ink-soft`, `text-muted`, `bg-v2-{violet,green,amber,pink,teal,coral}-soft` + `text-v2-*-ink`). **No hex colour literals** in `web/src` (ESLint fails the build); `packages/ui` may carry its own. No new colours/fonts/radii.
- Art: crop **everything visual from your board image** (consultant photos, ATS/client logos, bee/banner, chart art) with Python PIL into `web/public/ent/marketer/<page>/` (script: crop square around each avatar centre, 3× LANCZOS upscale, PNG; verify with a contact sheet via Read; delete the sheet). Boards are 1672×941 px. The shared banner `web/public/ent/marketer/help-banner.png` and the five demo photos/logos from Home already exist. Faces differ per board, so key photos by the API's `avatarUrl` (the mock returns `/ent/marketer/<page>/<slug>.png`); the real API returns `avatarUrl: null` unless the org has one, and the page falls back to initials. Characters (the bee) come only from the board crops or `web/public/ent/bee/*` via `EnterpriseMascot`; never redraw.
- Header: `PageHeader` (title + subtitle text exactly as on the board), `ClaimsMascot` + `ClaimsHelpCard` when the page draws its own bee/help card (see `MarketingHomePage.tsx`, the reference page).
- Honest data: every number on the board must come from the real API computed from real rows (counts, week/month deltas, sparklines from the last 8 buckets). A delta with no previous value is omitted. A list with no rows shows the board's empty state copy (doc 16 §5.2 has the empty-state text per page).
- Responsive: ≥1280 matches the board; below that cards stack, tables scroll horizontally in their card; 390px phone must have no horizontal page scroll.

## Backend rules
- Spring conventions: copy `OrgDashboardResource`/`OrgDashboardService` (constructor injection, `@RestController`, `@RequestMapping("/api/orgs/{orgId}/mkt/<page>")`, `@OrgPermissionRequired`, `@RequestAttribute(OrgPermissionRequired.MEMBERSHIP_ATTRIBUTE) OrgMembership me`, `@Operation` docs). The `orgId` in the path must equal `me.orgId()` (the annotation enforces it).
- Lists take `page`, `size` (cap 100), `q`, the board's filters and `sort`; return `{items, total, page, size}` plus whatever KPI/summary blocks the board needs, in ONE call per page where the board loads once (like Home). Write actions: `POST`/`PATCH` with `Idempotency-Key` where the codebase already uses it; validate with Bean Validation; audit through the existing audit service the same way other org writes do (find an example under `service/ent/members`); 404 not 403.
- Tests that MUST pass without Docker: Mockito/plain JUnit unit tests of your service (scope filtering — an unassigned consultant never appears and gets 404; empty org → empty states; KPI math; every filter) and of the resource (`MockMvc standalone` or direct call) — run them with `cd api && ./gradlew test --tests "<your test classes>" --no-daemon` (JDK 21 here is fine). Also write Testcontainers ITs in the repo's style (`Mkt<Page>IT` + a cross-tenant 404 case) for the real stack; they cannot run on this machine (no Docker): write them carefully, compile them (`./gradlew compileTestJava`), and say clearly in your report that they were not executed.
- Do not touch `application*.yml` except where truly required (say so in your report).

## Web tests (must pass)
`cd web && npx vitest run src/components/ent/marketer-ws/<page> src/lib/ent/marketer-ws` plus `npx eslint` on your folders; and `cd web && npm run build` must succeed (it needs `npm ci` at the repo root first, `node scripts/sync-parser-core.mjs` once). Component test: fixture from the board's rows → every KPI/title/column/row/button label from the board is on screen; empty → empty copy; failure → retry; 403/404 → "isn't part of your role". lib test: parse leniency. Write actions: test they call the BFF and never anything that submits for a consultant.

## Addendum (round 2, learned from round 1)
- **Repositories:** every repository under `com.dossier.api.repository.ent.mkt` must `extends org.springframework.data.repository.Repository<Entity, Long>` ONLY (never JpaRepository/CrudRepository) and every method must take `orgId` first (`save`/`saveAndFlush`/`flush` excepted; declare `<S extends E> S save(S entity);` yourself where needed). No `findById`, `findAll`, `saveAll`, `delete`, `count`: use `findByOrgIdAndId`, `findByOrgId`, `deleteByOrgIdAndId`, loops of `save`. `EntRepositoryContractTest` enforces it; run it (`./gradlew test --tests "*EntRepositoryContractTest"`): it still fails on the OLDER `repository/ent/talent/*` repositories (not yours, not fixable here), but no `Mkt*` repository may be listed.
- **Reuse the finished sibling services** instead of re-deriving formulas (`service/ent/mkt/{talent,resumes,jobs,matches,opportunities,streams,submissions,applications,interviews,followups,home}`): numbers on your page must equal the pages that own them. Do not edit them.
- **Gradle** on this machine is slow and memory-poor: always pass `"-Dorg.gradle.jvmargs=-Xmx1g"`, run one gradle at a time, use `--offline` when possible. Vitest: `npx vitest run <paths> --no-file-parallelism`. Do not run `npm ci`/`next build` (disk is nearly full) and do not use the browser pane; the owner does the visual pass.
- **Finish** by committing on your own `mkt-<page>` branch cut from `ent-talent-marketer` HEAD (`git checkout -b mkt-<page> ent-talent-marketer` first: your worktree may start on a stale base). The owner merges.
- **Shell chrome differs per board** (sidebar, top bar, search placement): ignore it, the shell is shared and off-limits; build only the page content area inside it (title/subtitle through `PageHeader`).
- The photos/characters on a board (including a new "girl with the bee" illustration on the Tasks board) must be cropped from the board image into your art folder and used as is.
